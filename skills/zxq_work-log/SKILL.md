# Work Log

项目长期记忆系统。记录关键功能变化、架构决策和方案演进。

定位：`session-handoff` = 短期记忆，`work-log` = 长期记忆。

## 执行流程

### Step 1: 分析当前会话

回顾对话内容，提取以下类型的关键事实：

- 完成的功能
- 关键架构/方案决策
- 重要重构
- 模块能力变化
- 核心算法调整

### Step 2: 生成日志条目

规则：

- 3~10 条
- 每条一句话
- 只记录**结果**，不记录过程
- 只记录**结论**，不记录代码细节

条目格式：`- [模块][类型] 一句话描述`

类型：

- `Feature` — 新增能力、功能、模块变化
- `Decision` — 重要设计决策
- `Decision Update` — 历史方案发生变化（需附原因）

### Step 3: 确定写入目标

获取今天日期 `YYYY-MM-DD`，目标文件：`.claude/memory/work-log/YYYY-MM.md`

### Step 4: 写入日志

**当天日期**：允许修改、合并、更新已有条目（未冻结）

**历史日期**：禁止修改，只能在当天日期下追加新的 `Decision Update` 条目

**文件不存在**：自动创建，首行为 `# Work Log - YYYY-MM`

### Step 5: 确认

告知用户本次写入了哪些条目。

## 禁止记录

- import 修改
- 变量名调整
- lint 修复
- 小型重构
- 代码片段
- 大段解释
- API 细节

## 推荐记录

- 功能能力变化
- 架构决策
- 方案切换
- 模块职责变化
- 核心算法调整
- 重要系统行为变化

## 时间线规则

- "天"是最小时间快照单位
- 历史日期禁止修改（项目真实演化过程，不是最终正确答案）
- 方案后续变化 → 追加新的 `Decision Update`
